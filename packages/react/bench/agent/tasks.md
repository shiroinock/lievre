# ベンチマークの課題

どのデザインシステムでも同じ文で解かせる5件の課題です。解答は1つのファイルにまとめ、課題の番号の名前（`T1.tsx` など）で部品を export します。データは解答の中に置き、保存や削除はメモリ上の処理で構いません。

## T1 設定画面

ワークスペースの設定画面を作る。

- 「ワークスペース名」の入力（必須）。補助文「メンバーに表示されます」。
- 「メールで通知する」の Switch。初期値はオン。
- 「保存する」ボタン。名前が空なら入力の下に「ワークスペース名を入力してください」と出し、保存しない。保存できたら通知（Toast）で「保存しました」と出す。

確認すること：入力とラベルが関連付いている／エラーが入力に関連付いている（`aria-describedby`・`aria-invalid`）／Switch がラベルで読み上げられる／主要な操作が1つ。

## T2 請求書の一覧

請求書20件を表に並べる。列は請求番号・取引先・金額・発行日。

- 金額と発行日で並べ替えできる。
- 10件ずつページ送りする。並べ替えはページを区切る前に全件に対して行う。
- 金額は桁を揃え、単位「円」は数値と書体を分ける。

確認すること：2ページ目に移っても並びが全件基準になっている／表に名前（caption）がある／金額の桁が揃う。

## T3 削除の確認

「プロジェクトを削除」ボタンから確認ダイアログを開く。

- ダイアログにはタイトルと、取り消せないことを伝える説明を付ける。
- 「キャンセル」と「削除する」を置く。「削除する」は危険な操作として見せる。
- 削除したらダイアログを閉じ、通知で「削除しました」と出す。

確認すること：ダイアログに名前と説明がある／閉じた後にフォーカスが戻る／危険な操作の見た目。

## T4 申し込みフォーム

- 「プラン」の選択（ライト・スタンダード・エンタープライズ）。
- 「支払い方法」のラジオ（請求書払い・クレジットカード）。
- 「利用規約に同意する」のチェックボックス（必須）。
- 「申し込む」で、未選択・未同意の項目にエラーを出す。すべて満たせば通知で「申し込みました」と出す。

確認すること：各項目にラベル／エラーが項目に関連付いている／ラジオがひとまとまりとして名前を持つ。

## T5 稼働状況

- 稼働率の数値カード：値 99.95、単位 %、前週比 +0.02 ポイント（上向き）。
- サーバー3台の状態：正常・注意・停止をバッジで出す。

確認すること：単位が数値と書体を分けている／状態が色だけでなく文字で伝わる／上向きの変化が言葉でも伝わる。
